1. 대상과 핵심 변경
======================================================================

기존 V34_2를 바탕으로 만든 별도 리팩터링본에 대한 설명입니다.
정식 Git 원본과 일반 V34_2 ZIP을 자동으로 교체하는 결과물은 아닙니다.
기존 화면의 바인딩·명령·공개 메서드 이름을 유지하면서 내부 책임을 나눴습니다.

기능 처리와 상태는 33개 Feature가 담당합니다.
MainViewModel이 구현하던 기능 계약은 독립 Context 33개로 옮겼습니다.
기능 사이의 요청은 Context를 통해 실제 담당 Feature에 직접 연결됩니다.

이전: 기능 A → MainViewModel 계약 구현 → 화면 모델의 전달 창구 → 기능 B
현재: 기능 A → 전용 협력 계약 → 독립 Context → 실제 기능 B

상태값을 복사해 두는 방식이 아니라, 기존 소유자의 상태와 같은 ref 저장 위치를
사용합니다. 화면에 연결된 기존 전달 창구도 호환성을 위해 유지합니다.

2. 역할별 변경 내용
======================================================================

가. 객체 구성과 기능 연결

FeatureComposition이 기능 객체를 생성하고 각 Context에 협력 대상을 연결합니다.
업무 Feature에는 구성 객체 전체 대신 해당 기능의 인터페이스만 전달합니다.
기능 객체 생성·상태 초기화·명령 구성·서비스 생성·이벤트 연결 순서는 유지합니다.

나. 속성 변경 알림

PropertyChangeCoordinator가 저장 대상 전환, 카운터 증가와 연관 속성 알림을
담당합니다. MainViewModel에는 가상 OnPropertyChanged 진입점과 기존
PropertyChanged 이벤트 발행을 남겼습니다. 이벤트 발행자도 유지합니다.

다. 영상 성능 집계

VideoPerformanceRecorder에 EO·IR 계측 상태 2개와 집계 메서드 4개를 옮겼습니다.
수신·표시 통계와 진단 로그만 담당하며, 연결이나 장비 제어를 요청하지 않습니다.
IVideoPerformanceContext는 필요한 카운터와 시나리오 14개만 제공합니다.
집계식·로그 항목·기록 주기와 기존 영상 처리 순서는 유지합니다.

라. 콜백과 서비스

FeatureCallbacks는 기존 화면 대상 콜백 33개를 보관하고 반복 조회 시 재사용합니다.
이벤트 등록·해제 대상과 기존 가상 메서드 호출 경로를 유지합니다.
FeatureRuntimeServices에는 기존 서비스·잠금·시계 인스턴스를 연결합니다.
별도 통신 객체를 중복 생성하지 않으며 서비스 사용 계약 13개를 유지합니다.

마. 파일과 서식

기존 어댑터 33개를 독립 Context 33개로 교체하고 구성·알림·계측 파일 5개를
추가했습니다. 전체 C# 파일은 203개에서 208개가 되었습니다.
한국어 설명·문단 간격·들여쓰기와 함수 사이 여백을 정리했습니다.
자동 생성 코드와 외부 패키지는 직접 정비하는 소스 범위에서 제외했습니다.

4. 객체지향 설계의 적용 범위
======================================================================

SRP: 화면 알림, 기능 간 연결과 영상 계측을 별도 책임으로 분리했습니다.

OCP: 사용 경계를 인터페이스로 유지하고 구현 연결은 구성 지점에서 처리합니다.

LSP: 기존 상속 관계·가상 알림·공개 바인딩 계약을 유지했습니다.
     새 상속 계층을 추가하지 않았습니다.

ISP: 기능별 계약과 영상 계측 전용 읽기 계약을 사용합니다.

DIP: 업무 Feature는 화면 모델·실제 TCP 클래스 대신 계약을 생성자로 받습니다.

상속·다형성은 기존 구조에서 유지하고, 합성과 위임으로 연결 의존성을 줄였습니다.
캡슐화는 실제 상태 소유자를 유지하는 방식으로, 추상화는 기능·서비스 계약으로
표현했습니다.

큰 PropertiesFeature·MoveControlFeature·VideoFeature와 일부 ref 상태 계약은
남아 있습니다. MainViewModel의 중첩 자료형을 공유하는 컴파일 의존성도 남습니다.
모든 Feature의 세부 책임 분리나 SOLID 전체 충족을 선언하는 단계는 아닙니다.

코드 표시 기준 — 이번 가독성 정리

단순 get/set은 접근자 본문을 한 줄씩 표시합니다. 상태 복사나 자동 속성으로
바꾸지 않았습니다. 조건 검사·알림·저장·복수 처리가 있는 접근자는 펼쳐 둡니다.
주석이 있거나 한 줄이 지나치게 긴 접근자도 기존 설명과 줄바꿈을 유지합니다.

같은 역할의 단순 대입·기능 객체 연결·초기화 목록에는 행마다 빈 줄을 넣지
않습니다. 생성·공유 자원 연결·상태 초기화처럼 단계가 바뀌는 곳을 구분합니다.
#region 앞에는 빈 줄을 두어 접은 상태에서도 구역 사이가 붙지 않게 했습니다.

새 Context 33개의 역할과 공유 상태·ref 의미, 생성 시 실행하지 않는 이유,
기능 구성 순서·콜백 재사용·이벤트 발행자 유지 이유를 한국어로 보강했습니다.
같은 전달 코드에 동일한 설명을 반복하기보다 묶음 앞에서 공통 원리를 설명합니다.

이번 정리에서 단순 접근자 3,236개, 대입 간 불필요한 빈 줄
1,004곳, 영역 구분 앞의 간격 132곳을 정리했습니다.
직접 작성한 코드와 생성 코드를 포함한 C# 208개를 대조했고,
생성된 Designer 파일은 편집하지 않았습니다.

8. 기능 이름 정리 - 2026-11-12 최종 보완
======================================================================

FeatureCallbacks의 임의 번호 33개를 기능·호출 목적에 따른 이름으로 바꿨습니다.
예: SaveAiEventsCallback17 → SaveAiEventsCallback
    QuerySpecialFeatureSupportCallback4 → QuerySpecialFeatureSupportCallback

같은 함수를 가리켜도 목적이 다른 두 호출은 별도 이름을 사용합니다.

RequestSystemDateTimeCommandCallback: 사용자가 누르는 시간 조회 명령
RefreshSystemDateTimeAfterSetCallback: 시간 설정 성공 후 장비 시간을 다시 조회
IsZonePresetCurrentForDisplayCallback: 화면에 표시할 구역 장면 선택
IsZonePresetCurrentForDetectionCallback: 탐지 판정에 적용할 구역 장면 선택

델리게이트 개수 33개, 호출 대상과 이벤트 등록·해제 관계는 그대로 유지합니다.

이전 버전명이나 탭 번호로 표현하던 내부 함수 4개도 역할 이름으로 변경했습니다.

InitializeWebAgentSession: WebAgent 연결 후 상태 조회와 세션 준비
ParseWebAgentTelemetryPacket: WebAgent 수신 상태 패킷 해석
CancelWebAgentPresetScan: WebAgent 프리셋 순회 취소
RunWebAgentPresetScanAsync: WebAgent 프리셋 순회 실행

ZoneViewProjection의 좌표·구간 판정 변수 8개, 파노라마 정합의 색상 가중치
마스크 변수 2개도 의미를 나타내는 이름으로 바꿨습니다.
프로토콜 Data1/Data2, 모델명, 채널 번호, 자료형 크기와 외부 API 이름은 유지합니다.

검증: C# 208개를 Debug·Release 문법 기준으로 대조했습니다.
허용한 식별자 치환 이외의 실행 토큰 변경이 없고, 두 구성의 빌드가 통과했습니다.
최신 Release의 회귀검사 1,854건, 공개 상태·API 2,988줄,
속성 알림 순서와 로그 결과 일치 검사를 다시 통과했습니다.
실제 장비 연결·제어 명령 송신은 수행하지 않았습니다.

9. 미사용 선언 정리 - 2026-11-12 추가 검증
======================================================================

Debug·Release와 두 프로젝트의 실제 컴파일 입력을 기준으로 전수 대조했습니다.
WPF 생성 코드, XAML 바인딩, 설정 파일과 코드의 문자열 참조도 확인했습니다.

96개 소스 파일에서 미사용 using 445개와 중계 프로퍼티 526개를 제거했습니다.
정리 대상 파일 기준으로 3,978줄을 줄였습니다. 실행 코드를 짧게 줄인 작업이 아니라,
책임 분리 후 실제 소비자가 없어진 선언을 제거한 작업입니다.

using은 네임스페이스를 짧게 쓰기 위한 선언입니다. using이 회색이라는 이유로
NuGet 패키지나 네이티브 DLL이 불필요하다고 판단하지 않습니다.
이번 작업은 패키지·DLL·프로젝트 참조를 삭제하지 않았습니다.

화면에 노출된 공개 속성, 장비 상태를 소유하는 Feature의 필드·프로퍼티,
독립 Context의 계약 구현, 프로토콜·통신·실행 순서는 유지합니다.
중복처럼 보여도 화면 바인딩이나 계약·이벤트 연결에 필요한 코드는 남겼습니다.

남아 있는 함수와 속성의 실행 토큰은 두 구성 모두 이전 코드와 일치합니다.
Debug·Release x64 빌드 및 자체 회귀검사 3,263건을 통과했습니다.
기존 공개 상태·API 2,988줄, 속성 알림 순서와 로그 출력도 동일합니다.
추가 검사는 삭제된 전달 창구 대신 실제 소유자와 계약의 저장 위치를 확인합니다.
이전 검사의 일부는 존재하는 전달 속성에만 적용되므로, 최신 검사 수를 별도 기록합니다.

실장비 연결·장비 명령 송신은 수행하지 않았습니다.
성능 향상 수치는 별도 측정 없이 확정하지 않습니다.
